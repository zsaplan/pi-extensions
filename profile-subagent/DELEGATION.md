# Delegation policy

## Goal and boundaries

Prefer useful allocation over maximizing child count. Guidance lives in existing tool descriptions and trusted child instructions—not a scheduler, automatic router, validator agent or site-specific workflow. Keep permissions, independent Sol/medium defaults, limits, result cap and queue unchanged. Never widen a role to fit an assignment.

## Parent decision

- Handle simple bounded work directly when launching a child adds more overhead than useful work.
- Combine substantial work sharing target, source and evidence when a trusted role permits that scope and its budget fits.
- Parallelize genuinely distinct, independent contexts. Finding count alone is not a reason to split; dependent work waits for prerequisites.
- Supply exact scope, target/environment where relevant, source/evidence paths, desired outcome and restrictions. Separate verified facts from leads; do not copy the whole conversation.
- Missing or unsuitable roles do not justify broader tools, larger limits or an unrestricted fallback.

The parent receives this guidance through the run-tool description, including codemode discovery. Search is for work worth delegating, not a mandatory step for every task.

## Evidence handoff

Within the role's output format, return one concise Markdown report with:
1. Per-item conclusion, separating observations from inference.
2. Decisive source/query references, observed results and target/freshness where relevant.
3. Verified, unresolved or not-applicable checks with reasons; retain failed attempts and important omitted checks.
4. Existing artifact references for deeper inspection—never invented paths or unauthorized evidence-file writes.

Reuse shared setup; avoid raw transcript duplication. Concision must not conceal contradictory evidence or uncertainty. The harness supplies actual private artifact locations.

Shared child instructions participate in the profile digest. Equivalent definitions in different checkout paths remain stable; parent routing instructions do not enter child context.

## Targeted parent verification

Inspect cited source/results behind material conclusions and resolve decision-changing gaps with the smallest relevant read or permitted query. Do not blindly approve a report or repeat the whole investigation. Failed/truncated results require inspection or an incomplete conclusion, not an automatic replacement child. Recheck mutable facts when freshness matters.

For postfix work, conditional checks cover natural/semantic identities, relevant successors/current consumers, active-state usability, exact replacement PK/FK targets, and relevant association/applicability coverage. Alternate identities require a plausible lead. These checks do not authorize wider scope or settings/customer-value retrieval. Current counts do not prove historical transfer completeness.

## Acceptance

- [x] Parent guidance is visible directly and through codemode.
- [x] Children receive evidence-handoff guidance without parent routing/history.
- [x] Shared-instruction changes alter profile digests; unchanged relocated definitions retain them.
- [x] Existing authority, auth, isolation, retrieval, concurrency, cancellation and accounting checks pass.
- [x] A fresh optional-delegation A/B trial used matched tasks, verification standard, original fork and parent model.
- [x] Actual routing, evidence checks, omissions, elapsed time, total model cost and parent context were reviewed.
- [ ] Repeated comparisons and genuinely different-context work before claims of general usefulness.

## Aggregate live result

One sequential, unblinded shared-context investigation compared parent-only work (A) with optional delegation (B). B independently selected one specialist for the entire bounded assignment, then checked decisive source and actual child SQL/results rather than repeating the database investigation. No tuning occurred during the group.

| Measure | A: parent only | B: optional delegation | Reduction |
|---|---:|---:|---:|
| Elapsed | 569.710s | 375.320s | 34.1% |
| Total reported model cost | $0.5845072 | $0.4680328 | 19.9% |
| Peak parent input tokens | 134,206 | 83,230 | 38.0% |
| Parent input growth | 83,320 | 31,620 | 62.0% |

Child usage reconciled exactly across messages, artifacts and parent nested totals; it was counted once. Fresh parent input usage was complete, with no fresh compactions or extra user messages. No recorded tool/query failures occurred.

No material classification error was found. Core conclusions agreed, but secondary coverage differed: A performed more alternative-identity, association-detail and schema-detail checks. Those checks supplied diagnostic precision without changing the main classifications in this trial. B retained material uncertainty rather than claiming exhaustive coverage or actual application impact.

This supports the current policy on shared-context work—not causal proof, identical coverage, verified billing, parallel speedup or general superiority. Model/provider load, caching and mutable evidence were not controlled. Earlier revisions used different instructions and are historical context, not controlled comparators.

Full original/failure evidence, source hashes and review records remain private. Public summaries intentionally omit target identities, database findings and investigation references.
